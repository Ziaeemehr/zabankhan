# Zabankhan Learning Tab — Product and implementation plan

Status: proposal, not implementation. No runtime changes authorized by this document.

## 1. Product positioning
Zabankhan is a companion to textbooks, classes and independent reading, not a replacement for teachers or a clone of Duolingo. Its differentiator is the integration of reading, dictionary, TTS, video, Leitner and structured practice. The README already describes French grammar and exam resources; inventory and reuse those before building replacements. No runtime LLM, API key, subscription or automatic AI-generated lessons is required. AI may assist maintainers offline during authoring, subject to review. Optional user-authored imports are a later convenience, not a core dependency.

## 2. Three learning paths
All paths share a concept catalog, content bank, exercise engine and learner profile. Users may switch paths without losing progress.
- **Structured course / Parcours guidé:** CEFR-aligned A1–C2 supplemental progression inspired by communicative textbooks (Édito, Alter Ego+, Tendances), not a reproduction or claim of full CEFR coverage. Select level, browse units, skip familiar material, revisit concepts. Each unit combines communicative objectives, grammar, vocabulary, pronunciation, reading, listening, oral and written production, culture and a bilan.
- **Exam preparation / Préparation aux examens:** independent profiles for TCF IRN, TCF Tout Public, DELF A1–B2, DALF C1–C2, TEF variants later. Choose target and optional date, practice by skill, learn strategies, take timed mock sections and review errors. Verify current official format, duration, scoring and skill requirements for each variant before publication. TCF/TEF target levels are not separate diplomas. Keep practice mode distinct from exam mode (no dictionary, hints or pause where official rules disallow them). Scores are unofficial; do not claim calibrated CEFR or official equivalence. Speaking/writing use prompts, rubrics, model answers and self-assessment; no automatic proficiency claims.
- **Personalized learning / Entraînement ciblé:** choose concepts from a textbook or class, grammar, vocabulary, listening, reading, pronunciation, workplace or daily life. Search by topic, level and concept; build a daily plan from selected concepts, due reviews and errors. Optional textbook mappings by edition/unit are bibliographic pointers only, not copied content.

## 3. Curriculum
Use CEFR Companion Volume descriptors as outcomes; use multiple textbooks as inspiration for progression, not as content sources. Consult Grammaire progressive, Vocabulaire progressif, Phonétique progressive and Grammaire en dialogues for coverage planning. Produce original texts and exercises. Maintain a matrix of level, communicative outcome, concept, prerequisite, skill and assessment. CEFR does not mandate a universal grammar syllabus.
Suggested B1 sequence (illustrative): memories (past tense contrast); relationships (relative pronouns); work/study (reported speech); culture (conditional); feelings (subjunctive); media (passive); environment (cause/consequence); travel (pluperfect); technology (concession); regrets (past conditional); future plans (future perfect); argumentation (connectors). A1 starts with introductions and basic transactions; A2 expands everyday autonomy; B2 emphasizes argumentation and nuanced comprehension; C1/C2 deferred.
Example unit: Culture et spectacles — listen to an original concert dialogue, read a review, study criticism vocabulary, learn future-in-the-past, practice intonation, record an opinion, write a short review, complete a bilan. Each micro-lesson takes roughly 5–15 minutes.
Example: J’espérais que ce serait une expérience inoubliable. Explain conditionnel présent as future-in-the-past; contrast with future simple; provide examples and contextual exercises. Save banal, inoubliable, s’attendre à to existing vocabulary review by explicit user action.

## 4. UX and navigation
Add Learn tab only after navigation audit; avoid crowding existing tabs. Landing: active language/level, continue last activity, daily plan, three paths, downloaded content, progress and error review. Empty state offers small starter pack and clear download size. Allow browsing without enrollment. Lesson: objective, short explanation, tappable text, TTS, examples, common errors, practice, summary. Reuse existing reader/dictionary/Leitner interactions rather than duplicate them. Exercise UI: progress, answer input, submit, feedback explaining why, next, retry later. Exam UI: timer, section navigation, submission confirmation, post-exam review. Support Persian RTL mixed with French LTR, English UI, dark mode, accessibility, large fonts, tablet layouts and screen-reader labels. Avoid punitive streaks; optional goals and reminders.
Daily plan default 15 min: 5 new concept, 4 practice, 3 Leitner, 3 error review. Configurable time and rest days; no forced new lessons when review is overdue.

## 5. Exercise engine
Data-driven renderer registry, deterministic scoring and separate practice/exam policies. MVP: single/multiple choice, true/false, gap fill, ordering, matching, reading comprehension, TTS listening and dictation. Later: conjugation tables, error correction, translation with accepted variants, recorded shadowing and self-assessed production. Normalize Unicode NFC, whitespace and punctuation according to question policy; preserve meaningful accents and apostrophes, allow explicit alternatives; never silently accept wrong grammar. Provide hints, explanations, distractor rationales, stable item IDs and seeded shuffling. TTS is synthetic and not a substitute for authentic exam audio. Open answers without reliable keys are self-assessed. Save attempts and resume interrupted sessions; do not count retries as independent first attempts.

## 6. Learner model and adaptive review
Track per language: selected level, goals, completed activities, attempts, concept/skill evidence, review due dates, exam sessions and downloaded packs. Keep vocabulary scheduling in existing Leitner system; concept/error review separate but coordinated. Use transparent rules: prioritize due errors, then weak concepts with sufficient evidence, then next eligible lesson; mix previously unseen items and spaced retrieval. Example intervals 1/3/7/14 days, adjusted after errors. Show sample counts and recent first-attempt accuracy, not unsupported mastery percentages. A concept graph supports prerequisite remediation (future stem and imparfait endings before conditional morphology; separate semantic use). Graph must be acyclic for hard prerequisites. Initial level self-selection; later diagnostic by skill with uncertainty and no claims for untested speaking/writing. Backups include learning progress, stable IDs and pack references, not redownloadable assets; test restore and merge behavior.

## 7. Repository decision (proposed ADR)
Options: app repo is convenient for schemas, tests and tiny fixtures but couples content releases to app work; zabankhan-dict could host content but mixes lexical datasets with pedagogical editorial lifecycle; dedicated **zabankhan-learn** is recommended for independent versions, contributions, validation and multi-language growth. A separate repo alone does not reduce APK/IPA size: exclude full packs from bundled assets and download on demand. Do not create the repo until owner approves. App repo owns runtime contract, schema compatibility and small fixtures; dict repo remains lexical; learning repo owns source content, authoring pipeline, licenses and published pack artifacts. Avoid duplication of dictionary data; reference lemmas/language and resolve locally with graceful fallback.
Proposed layout:
    catalog/
    schemas/ (generated or pinned from app contract)
    courses/fr/{A1,A2,B1,B2}/
    concepts/fr/
    exercises/fr/
    exams/fr/{tcf-irn,tcf-tp,delf}/
    media/
    tools/
    licenses/
    tests/
Publish immutable compressed packs via GitHub Releases initially, not raw Git files or Git LFS as runtime delivery. Public catalog points to immutable release assets. Evaluate CDN/object storage if release limits or traffic require it. Keep source JSON/Markdown human-editable; compile to compressed JSON or SQLite after measuring query performance. Split by language, level and unit/skill; optional audio packs separate. Shared concept IDs and dependencies avoid duplication across paths. Tiny starter content only if measured bundle budget permits.

## 8. Pack contract and download lifecycle
Manifest fields: packId, language, level, kind, version, schemaVersion, minAppVersion, dependencies, compressedBytes, installedBytes, sha256, asset URL, locale availability, license, attribution. Catalog version and trusted origin pinned; HTTPS, checksum verification, optionally signed catalog with pinned key for stronger authenticity. Stable content IDs never reused; version changes preserve progress; aliases/migrations for renamed concepts; retired items remain interpretable in history. Reject unsupported schema, missing dependencies, path traversal, oversized archives and invalid references. Download to temporary location, verify size/hash, validate schema, atomically install; preserve old pack on failure. Support cancellation, retry, low storage, offline use, update notifications, removal and redownload without losing progress. Never execute downloaded code or scripts. Restrict remote media and links; use local TTS by default. No learner data sent to content host beyond ordinary download requests.
Initial engineering targets (measure before committing): starter fixture under 1 MB compressed, text-only unit packs under 2 MB compressed where practical; audio separately listed. Show actual sizes and storage use. Test interrupted downloads, corruption, incompatible versions, low storage, offline launch and update rollback.

## 9. Data model
Entities: Concept(id, language, CEFR range, prerequisites, outcomes); Lesson(id, conceptIds, blocks, locale, duration, source/license); Exercise(id, type, prompt, options, answerSpec, feedback, conceptIds, skill, difficulty, mediaRefs); Unit(id, objectives, ordered lessonIds); Path(id, unitIds, selection policy); ExamProfile(id, variant, formatVersion, sections, time limits, scoring policy, official source and checked date); Attempt(id, itemId, itemVersion, timestamp, firstAttempt, outcome); ReviewState; PackManifest. Localize explanations separately from target-language text. Use stable IDs across Persian/English translations. Validate referential integrity, prerequisite cycles, correct answers, duplicate items, accessibility metadata and licensing.
Example exercise: id fr.b1.future-in-past.001; prompt “J’espérais que ce ___ une expérience inoubliable.”; options sera/serait/soit/était; key serait for the intended future-in-the-past reading (state that restriction explicitly); explanation and alternatives; tags fr, B1, grammar, future-in-past. This is an illustrative item, not a released question.

## 10. Content production and QA
Define syllabus and coverage matrix first. Authors create original content; optional maintainer-side LLM generates drafts using structured schema. Automated checks for schema, references, answer keys, duplicates, missing feedback, localization and licenses. Independent linguistic/pedagogical review for ambiguity, level, naturalness and distractors; native-speaker review of audio/idiom where possible. Never treat model agreement as proof. Record author, reviewer, revision, provenance and license. Do not copy commercial textbook texts/exercises/audio or official exam papers without permission; use original exam-style questions and official public format specifications. Select an explicit content license only after owner decision; third-party assets retain their own compatible terms. Publish via CI only after review; support error reports and corrected pack releases.

## 11. Implementation phases and acceptance gates
P0 — audit existing grammar/exam assets, navigation, persistence, sync, reader/TTS/dictionary APIs, pack download code and Android/iOS parity. Produce reuse map and ADR; confirm repository/license choices.
P1 — schema, fixtures, validation CLI, local repository interface, exercise scoring tests, stable IDs. Gate: invalid content rejected, deterministic scoring, no network/LLM needed.
P2 — Learn navigation, concept browser, lesson renderer, exercise UI, progress and error review. Gate: A1 and B1 sample units complete offline on Android/iOS; dictionary and Leitner reuse; RTL/dark/accessibility tested.
P3 — catalog and on-demand pack manager, backup/restore integration, release pipeline. Gate: install/update/delete/corruption/rollback tested; APK/IPA size measured against baseline; progress survives updates and restore.
P4 — pilot French supplemental bank: 20 concepts across A1–B1, ~15–20 reviewed items each, one complete A1 and B1 unit, original reading/listening samples. Gate: reviewed content, no ambiguous keys, learner usability feedback. This is not full level coverage.
P5 — expand A1–B2, daily planner, concept graph and targeted practice; optional diagnostics. Gate: due reviews, weak-topic selection, path switching and evidence counts tested.
P6 — exam prep pilot (choose TCF IRN or DELF B1/B2 based on demand), verified exam profile, timed sections and self-assessment rubrics. Gate: format verified against current official sources, no official score claims.
P7 — additional exam variants, C1/C2 and languages; optional validated lesson import/export for externally authored content. No runtime AI required.
Long-term indicative content targets, not commitments: 100 concepts, 2,000 exercises, 100 reading and 100 listening activities, 50 vocabulary sets and 10 mock exams. Expand only after quality and usage evidence.

## 12. Testing and success metrics
Unit tests: scoring, normalization, scheduler, graph, migration, schema compatibility. Integration: pack lifecycle, offline operation, dictionary lookup, Leitner save, backup restore, exam timing. UI: Android/iOS, RTL, dark mode, large text, interruption/resume, accessibility. Content: manual sample review plus automated validation for every release. Measure opt-in or local-only lesson completion, return to practice, review completion, first-attempt accuracy on unseen items, download failures and installed size; no mandatory analytics or collection of personal study content. Compare learning outcomes cautiously; engagement is not proficiency.

## 13. Non-goals and open decisions
No full textbook replacement, no runtime LLM, chatbot, automatic free-text grading or mandatory account. No claim of official CEFR certification. No repository creation, code implementation or asset migration in this documentation branch. Owner decisions: dedicated repo name/license, starter pack budget, first exam variant, exact tab placement, supported locales and audio strategy. Technical estimates depend on P0 audit; no schedule or staffing commitment yet.
